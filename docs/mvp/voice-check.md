- 실차에도 같은 이미지 구성이면 **표준 TTS API로는 소리가 안 납니다.** 실차·다른 트림에 Google TTS가 들어 있는지는 [미확인]입니다.

## 2. 부드러운 여성 음성 안 (2026-10-24 시도 — **샘플 만들지 못함**)

> 결론: **이번에는 샘플 wav를 하나도 만들지 못했습니다.** `evidence/voice/`와 Mac `~/Downloads/hmg-voice/`에 **wav가 없습니다**(그래서 Mac 폴더도 만들지 않았습니다). 지금 바로 쓸 수 있는 안은 **3절(미리 녹음한 오디오 조각)**입니다.

### 2-a. 계획했던 녹음 (실행 불가)

| 화자 | 프리셋 A (속도 0.9 / 피치 1.0) | B (0.9 / 1.1) | C (0.85 / 1.05) | 기본값 |
|---|---|---|---|---|
| seoyoon | 만들지 못함 | 만들지 못함 | 만들지 못함 | 만들지 못함 |
| haeun | 만들지 못함 | 만들지 못함 | 만들지 못함 | 만들지 못함 |

문장 2개 × (프리셋 3개 + 기본값) × 화자 = 0개 생성. 길이(초)·네트워크 여부도 측정하지 못했습니다.

### 2-b. 만들지 못한 이유

1. **표준 TTS 경로가 막혀 있음** — 1-a 참고. 프로브의 `synthesizeToFile()`은 엔진이 없어 실행되지 않았습니다(`files:0`).
2. **Pleos TTS SDK로는 파일을 만들 수 없음** — `speak()`는 차량 오디오로 바로 재생만 하고 파일 출력이 없습니다. **속도·피치 조절 API도 없어서 프리셋 A/B/C 자체를 적용할 수 없습니다.** 화자 선택(`setSpeakerType`)만 가능합니다.
3. **재생을 녹음할 수도 없음** — 에뮬레이터가 `-no-audio`로 실행 중이고, AVD/에뮬레이터 설정은 바꾸지 않기로 했습니다.
4. 이번 프로브 APK는 Pleos TTS SDK를 쓰지 않습니다(표준 API만 시험).

### 2-c. 다음 할 일 (제안)

- **청취 비교가 필요하면**: Pleos TTS SDK로 `setSpeakerType(seoyoon / haeun / eunwoo / sanghyeok)` × 문장 2개를 순서대로 `speak()`하는 작은 프로브를 만들어, **실차나 오디오가 켜진 에뮬레이터**에서 대표님이 직접 들어 보시는 방식이 유일합니다. 속도·피치 조정은 이 SDK로는 불가합니다.
- 서버 모드 품질을 들으려면 Pleos Playground clientId/secret 등록과 네트워크가 필요합니다(온디바이스는 등록 불필요). → 10/28 Q&A 질문 후보: "TTS SDK에 속도/피치 또는 SSML 지원 계획이 있는지, 화자별 샘플 음성을 받을 수 있는지".
- **부드러운 여성 음성을 확실히 원하면 3절 안(상업 이용 가능한 TTS로 미리 녹음한 클립)**이 품질·일관성 면에서 가장 안전합니다.

## 3. 대안: 미리 녹음한 오디오 조각

> **(10/24 11:40 KST 확정) 미리 녹음한 클립을 주 음성으로 씁니다.** 재생 순서는 클립 → 기기 TTS → 차임입니다. 확정 문장 목록과 파일 규칙은 **3-d**에 있습니다. 생성 서비스(Azure S0 / Polly)는 대표님 승인 대기이며, 가입한 곳은 없습니다.

기기 TTS 엔진에 좋은 ko-KR 여성 음성이 없거나 차종마다 품질이 다를 경우를 대비한 안입니다. 문장 수가 적고 바뀌는 부분이 `{왼쪽/오른쪽}`, `{유종}`, `{숫자}` 세 가지뿐이라, **미리 만든 오디오 파일을 앱에 넣어 재생**하는 방식이 현실적입니다. 오디오 파이프라인(audio attributes, `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`, 차임 폴백, raw 클립 재생)은 지금 그대로 씁니다.

### 3-a. 조각 이어붙이기 설계

#### (1) 문장 나누기 원칙

- **문장 경계(마침표)에서만 자릅니다.** 한국어는 어절 사이 억양이 이어지기 때문에 `"터널이" + "한 곳" + "있어요"`처럼 문장 중간을 자르면 이음새가 바로 티 납니다. 마침표 뒤에는 원래 쉼이 있어서 이어붙여도 자연스럽습니다.
- 바뀌는 단어가 문장 안에 있으면 **슬롯을 따로 녹음하지 말고 문장 전체를 경우의 수만큼 녹음**합니다. 이번에는 경우의 수가 적어서 이 방법이 가능합니다.
- 모든 조각은 **같은 음성, 같은 설정(속도/피치/감정), 같은 회차**로 생성합니다. 나중에 한 조각만 다시 만들면 음색이 미세하게 달라질 수 있습니다.

#### (2) 조사·어미 맞추기 (예요/이에요, 은/는)

| 앞말 | 받침 | 어미 | 예 |
|---|---|---|---|
| 휘발유차·경유차·LPG차(엘피지차)·전기차·하이브리드차 | 없음 (`차`) | **-예요** | 휘발유차예요 / 전기차예요 |
| 왼쪽·오른쪽 | 있음 (ㄱ) | **-이에요** | 왼쪽이에요 / 오른쪽이에요 |
| 주유구·충전구 | 없음 | **-는** | 주유구는 / 충전구는 |

- 유종 단어가 모두 `~차`로 끝나서 `예요`로 통일됩니다. 다만 `휘발유예요`처럼 `차`를 빼면 `유`(받침 없음)라 역시 `예요`, `LPG`는 `엘피지`로 읽혀 `예요`가 맞습니다. 대본 텍스트에는 **`엘피지차예요`처럼 소리 나는 대로** 써야 TTS가 잘못 읽지 않습니다.
- **주유구/충전구 구분:** 전기차는 `충전구`라고 해야 합니다. LPG차도 일상적으로는 `충전구`라고 부르는 경우가 많습니다(문구 확인 필요). 하이브리드(HEV)는 `주유구`, 플러그인 하이브리드는 둘 다 있어서 이번 범위에서 제외하거나 따로 문장을 만듭니다.
- **숫자 읽기:** `곳`은 고유어 수사를 씁니다 → `한 곳, 두 곳, 세 곳, 네 곳, 다섯 곳 … 아홉 곳`. TTS에 `1곳`을 넣으면 `일 곳`으로 읽을 수 있으니 **대본은 한글로** 씁니다. 거리(`300m`)는 한자어 수사 → `삼백 미터`.

#### (3) 조합 수 세기

| 문장 틀 | 변수 | 조합 수 | 녹음 방식 |
|---|---|---|---|
| "이 차는 {유종}차예요. {주유구/충전구}는 {방향}이에요." | 유종 5 × 방향 2 | **10** | 문장 전체 10개 (또는 앞문장 5 + 뒷문장 4 = 9조각, 마침표에서 이어붙이기) |
| "오늘 길엔 터널이 {한~아홉} 곳 있어요." | 1–9 + 0개("오늘 길엔 터널이 없어요.") | **10** | 문장 전체 10개 |
| "{거리} 앞에 터널이 있어요." (선택) | 거리를 구간으로 고정: 100/200/300/500m, 1km | **5** | 문장 전체 5개 |
| 기타 고정 문장 (시작/종료/오류 안내 등) | — | 약 5–10 | 문장 전체 |
| **합계** | | **약 30–35개** | |

- 거리를 임의 숫자(예: 347m)로 읽어야 한다면 `일~구 + 십/백/천 + 미터` 조각(약 20개)을 이어붙여야 하는데, 억양이 어색해집니다. **거리는 정해진 구간으로 반올림해서 안내하는 쪽을 권합니다.**
- 9가 넘는 터널 수처럼 범위를 벗어나는 값은 숫자 없는 문장("오늘 길엔 터널이 여러 곳 있어요.")이나 차임으로 대신합니다.

#### (4) 파일 형식과 후처리

- **형식:** 기존 `announce_chime.wav`와 같은 재생 경로를 쓸 수 있도록 **WAV, PCM 16-bit, 모노, 24kHz**를 기본으로 권합니다. 대부분의 클라우드 TTS가 24kHz로 출력하므로 48kHz로 올려도 음질이 좋아지지 않습니다(사람 성우 녹음본만 48kHz로 받아 24kHz로 내림). 용량이 신경 쓰이면 OGG(Vorbis/Opus 64kbps)를 씁니다.
- **음량 맞추기:** 모든 조각을 **약 -16 LUFS, True Peak -1 dBTP**로 맞춥니다. 예: `ffmpeg -i in.wav -af loudnorm=I=-16:TP=-1:LRA=7 -ar 24000 -ac 1 out.wav` (2-pass 권장). 2–3초짜리 짧은 클립은 측정값이 흔들리기 쉬우니, 처리 후 귀로 크기를 한 번 더 맞춥니다. 차임과 음량 차이도 같이 확인합니다.
- **앞뒤 무음 자르기:** `silenceremove`로 앞뒤를 자르고 **앞 30ms, 뒤 100ms 정도만** 남깁니다. 클릭음을 막으려고 5ms 페이드 인/아웃을 넣습니다. 이어붙이는 경우 조각 사이에 150–250ms 쉼을 코드에서 넣습니다.
- **APK 용량 추정** (클립 35개 × 평균 2.5초 = 약 90초 기준):

| 형식 | 초당 크기 | 합계 |
|---|---|---|
| WAV 48kHz/16-bit 모노 | 96 KB/s | 약 8.4 MB |
| **WAV 24kHz/16-bit 모노** | 48 KB/s | **약 4.2 MB** |
| OGG 약 64kbps | 8 KB/s | 약 0.7 MB |

→ 24kHz WAV로도 5MB 미만이라 공모전 앱에는 문제없는 크기입니다.

#### (5) 기존 raw 클립 재생 재사용

- `announce_chime.wav`를 재생하는 raw 클립 경로를 그대로 씁니다. `res/raw/vo_fuel_gasoline_left.wav`, `vo_tunnel_3.wav`처럼 **키 → 리소스 ID 매핑 표** 하나만 추가하면 됩니다.
- 재생 순서: **녹음 클립 → (없으면) 기기 TTS → (그것도 안 되면) 차임**. audio attributes와 `GAIN_TRANSIENT_MAY_DUCK` 포커스 처리는 지금 코드를 그대로 따릅니다. 이어붙이는 경우 포커스는 **한 번만 요청**하고 조각을 연달아 재생한 뒤 반납해야, 조각 사이에 음악 볼륨이 오르내리지 않습니다.
- 문장 키 → 파일 매핑을 데이터로 빼 두면, 나중에 음성을 바꿀 때 파일만 교체하면 됩니다.
